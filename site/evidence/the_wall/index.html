How the stage word is derived. A node's stage is a pure function of its mapped atoms' levels (docs/design/maturity_map.yaml level_current vs level_target): LIVE = every mapped atom at target; BUILDING = at least one below target; PLANNED = none started (all at level 0). Phase A does NOT compute stage -- it fixes the mapping and proves it coheres (every node has atoms, every atom ref is live, diagram and mapping agree on the node set). 'declared_stage' records the stage the live site currently HAND-SETS, so Phase D can flag drift between it and the computed stage.

Every atom behind this claim is at its target level, which is what makes the stage word “Live”. It is not a judgement; it is the rule below applied to the levels in the table.

The diagram declares Live; the derivation computes Live. They agree.

“Tests naming it” counts test functions in modules under tests/ whose source names the atom id; map-wide registry modules (which name ten or more atoms) are reported separately so one shared module cannot inflate every atom's count. The counts are collected at build time from the test tree — the run that proves them green is the publish gate itself (pytest tests/), which this page's own gate is part of. “Level-move record” is the append-only gate-authorizations ledger (R16): an atom with no row has had no recorded move, and the page says so rather than implying one.
