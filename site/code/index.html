The code

Every module Poesys is built from is a star, sized by its lines, and every import is a line between two stars. Poesys is two programs: the world, a simulated GB energy market built on the real 2016–2025 record, and the company, an energy supplier inside it that may know only what a real supplier could. The wall between them has one sanctioned doorway, the seam. Blue lines cross the wall through the seam; red ones go round it. Laid out from the committed code at each publish.

What each cluster is

Two clusters on each side of the wall, because each side was built in two stages, not because the jobs differ that much. Written 24 Oct 2026 from a review of the code; the review's rulings are in the stretch log.

ClusterSideWhat it is
simworldThe market: the real Elexon, NESO and weather record, prices as they stood at each moment, and forward curves.
simulationworldThe households and the run: demand, life events, payments, settlement, and the runners (run_phase*) that move both programs through time and hand the company only what it could see.
companycompanyThe supplier: pricing, billing, customers, trading, compliance. It sees the world only through company/interfaces, the seam.
saascompanyAlso the supplier: the first business layer (July 2026), with customer value, churn and cost to serve, never folded into company. Two of its models are still read by the world: three of the crossings below.
interfaceneitherShared data shapes for the seam.
toolsoutsideScripts, generators, checks and run entry points. Many are run by hand, so they have no importer by design.
backgroundoutsideThe machinery that runs the project itself: the daemons, gates and logs. Never an input to the company.
functionsoutsideThe website's server-side handlers.

A star with no line is a module nothing else here imports. In tools that is mostly a script. In company and saas it is code that its tests import and no run ever reaches: built, tested and unused.
