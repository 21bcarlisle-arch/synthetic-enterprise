## What the shape means

The report is not merely imported — it has become the place where domain figures are
COMPUTED, and the suite validates those figures by calling renderer internals. So the
debt is not an import list to unpick; it is that a rendering owns computations. Paying
it means giving each of those sections a home outside the renderer and repointing its
tests, which is a rebuild of the reporting layer.

## What is already true

No production code reads a COMPUTATION out of the report any more. The one that did --
`tools/generate_dashboard_data.py`, for `populate_compliance_scorecard` -- now imports
it from `saas/reporting/compliance_scorecard_population.py`, which both surfaces share
so they cannot disagree about whether an obligation is GREEN.

Two import edges remain and are frozen WITH REASONS rather than waved through:
`tools/run_annual_report.py` renders the report (a renderer's own runner is not other
code reading it), and `tools/publish_report_gist.py` imports two PATH CONSTANTS to know
where the artefact lives. The second is real, small debt: a filename should not require
importing a 9,700-line renderer. It is left because it touches the publish path and the
instruction was explicitly narrow.

A NEW production importer fails the commit, so this cannot grow on the side that matters.
