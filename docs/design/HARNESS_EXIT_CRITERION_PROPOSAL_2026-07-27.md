# Harness exit criterion — proposal for director ratification (2026-07-27)

**Answers PROBLEM TWO of `DIRECTOR_RULING_HARNESS_INVESTMENT_AND_ITS_EVIDENCE_2026-07-27`.** Only the ratification of this criterion returns to the director; everything else in that ruling proceeds. This is a *candidate to beat*, framed against the advisor's own starting point and its three named weaknesses.

## The advisor's candidate (the starting point)

> *A full week of content work with zero director interventions for stalls, classes or draw failures.*

Named weaknesses (the ruling states them): **(a)** a week is arbitrary; **(b)** "content" needs a definition that cannot be gamed; **(c)** zero-interventions conflates a *stall* with a *legitimate director decision*.

## The proposal — evidence-based, not time-based

> **The harness is "done for now" when THREE consecutive product-content atoms each reach their next director-ratified level with their declared exit criterion landed, across a span in which the STALL-class intervention count is ZERO — director DECISION-class touches unrestricted.**

Three moving parts, each measurable from primary state (git history, the maturity map, the `gate_authorizations.jsonl` ledger, the fidelity-evidence ledger, and the §5 backlog surface):

### 1. "Content" — the ungameable definition (fixes weakness b)

A level advance counts as **content** iff ALL hold, each mechanically checkable:

- The atom is a **product atom** — lane in `{W*, D, B, E, C, F, G-product, SITE}`, i.e. it deepens the world, the company, or a business surface. Explicitly **NOT** `H_harness` and **NOT** a `close_to_learn` machinery atom. (Reuses the existing product/machinery split, `G11_activity_cost_utilisation`.)
- The advance lands its **declared exit criterion** — a fidelity-ledger row that *moved* against an *unchanged* baseline, **or** an acceptance test tied to a named Board Spec / `real_world_twin` that now passes, **or** an R11-verified change to the live business surface.
- It is **NOT** any of: a test-count increase alone (R6/NEXT_PHASE rule), a HARDEN re-verify (demoted, §1 of the coherence ruling), a harness/mechanism/observability edit, or a level move with no fidelity delta.

This cannot be gamed by machinery churn relabelled as content: the lane filter + the fidelity-delta requirement are both primary-state facts, not self-assessments.

### 2. "Zero interventions" — stall vs decision (fixes weakness c)

Director touches split into two classes, both already detectable in primary state:

- **STALL-class (the metric — must be ZERO across the span):** a supervisor idle-turn with atoms available; a draw-failure / `map_exhausted` while below-target or un-minted work exists; the director hand-typing the next atom (the R3 incident); a HARDEN-while-content-unminted draw (§1 of the coherence ruling); any `[ACT]` escalation the director later rules was reversible (`MAKE_IT_STICK` anti-decay metric). Each has an existing detector.
- **DECISION-class (unrestricted — expected, not a failure):** a level ratification in the ledger; a `FRONT_OPEN` / `BUILD_OPEN`; a curriculum/values call (R13); a one-way-door approval. These are the director exercising his reserved authority, which the whole system is *designed* to route to him — counting them as failures would perversely punish correct escalation.

### 3. "Three consecutive" — not a duration (fixes weakness a)

The unit is **delivered content**, not elapsed time. Three *independent* product atoms reaching their ratified next level shows a *sustained pattern across different work*, not a single lucky run, and is reachable in days — so the criterion rewards throughput, never the clock. `N = 3` is itself a dial the director sets at ratification; I propose 3 as the smallest count that distinguishes a pattern from a one-off.

## Falsifiability — a test the machine can FAIL

The criterion **FAILS** (resets the consecutive counter to zero) the instant EITHER: a STALL-class event is detected, OR a claimed content advance is found to lack its exit-criterion delta (a level move with no moved fidelity row / no passing spec-tied test / no R11 live-surface change). It is computed each tick from git + the ledger + the fidelity register + the §5 backlog surface, and the current count + last-reset-cause is published in the daily self-note. Mechanised as an R15-both-ways test before it counts as a control (a synthetic stall must reset it; three clean content advances must satisfy it).

## What ratification buys

Once ratified, this is the single answer to *"is the harness done for now?"* — held to me, checkable against primary state, not asserted by feeling. Until the counter reaches N, harness/HARDEN work stays demoted below content (coherence ruling §1); when it reaches N, harness investment may resume as the drawn work, having *earned* it with evidence — a company the harness built while nobody watched.
