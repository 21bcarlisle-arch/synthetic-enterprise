## The state, and what is new about it

`SEAT_FINDING_THE_SITE_LANE_IS_RED_AT_HEAD_AND_THE_TREES_FIX_DELETES_SIXTEEN_CONTROLS_2026-09-07.md`
established that three controls in `site/test_harness_delivery_record.py` fail in a clean HEAD
extract because `site/data/delivery.json` renders a withheld message instead of the product table,
and that **no lane can land a site change** until it clears. That is still true and this does not
close it.

**What is new is that the remedy the withheld message itself names could not be run.**
`site/data/delivery.json` publishes, to a reader:

> *the product-ceiling artefact in this tree predates the ceiling/floor split, which IS the finding.
> It is withheld rather than shown as a list of numbers whose kind is unstated: re-run
> `python3 -m tools.r4_product_ceiling --save`.*

That command raised `KeyError` and wrote no artefact at all. `tariff_fit_ceiling` has two returns
and only the bounded one carries `households_above_the_reference`; `headline()` read the key
unconditionally. On this book the arm takes its **data-availability refusal** — 0 households carry
a rate, a market reference and an electricity EAC together, against a floor of 20 — so every
invocation died on the branch that exists to be taken rarely.

**A published surface named a command that could not run, and the gate that surface feeds blocks
every lane.** The 2026-09-07 finding says the repair "belongs to the lane that owns R4"; it could
not have been done by that lane either.

## What this commit does and does not do

**Repaired:** `headline()` now states the refused arm's coverage as a refusal, in the arm's own
words, and no longer calls an unbounded arm one of "both bounded arms" — which was the flattering
reading of a data-availability failure. Two controls, each mutation-proven (reverting the branch
reproduces the `KeyError`; making the refusal wording unconditional reds the bounded witness).

**NOT done, and deliberately:**

* **The artefact was not regenerated.** `docs/observability/r4_product_ceiling.json` in the shared
  working tree currently holds a *different shape entirely* — top-level keys `channels`,
  `channels_computed`, `channels_refused`, `run_output`, and no `tariff_fit`. Something other than
  this tool wrote it and it is uncommitted. Running `--save` now would overwrite another lane's
  in-flight file with a 0-household refusal. **Whoever owns that file should say what it is before
  anything writes over it.**
* **The three red controls are still red**, because clearing them needs the publish-cycle
  regeneration of `site/data/delivery.json` *and* the decision about the sixteen controls the
  working tree deletes — both of which the 2026-09-07 finding correctly says are not a passing
  lane's to make.
