# WORKER REPORT — a consolidation's severity is written once at render and never re-read

**Severity:** RECORDED · **Lane:** H_harness

**Date:** 2026-08-12 · **Draw:** RUNG 1c (OPS12 clause 3), lane `H_harness`, 8 live BLOCKING findings
**Subject:** `background/finding_classes.py::check` — the class layer above OPS9's discharge
**Outcome:** the release valve now exists one layer up and is checked; three of the eight H_harness
blockers are class documents whose release path was previously inert in principle.

---

## The finding

Yesterday's tick gave an individual finding a way to be released: a structured, filesystem-checked
`**Discharged:**` header that reads a document down to `RECORDED`. That is the correct valve, and it
works.

Three of the eight blockers now standing in `H_harness` are not individual findings. They are **class
documents** — `CLASS_CONTROLS_THAT_CANNOT_FAIL` (19 instances), `CLASS_PUBLISH_GATE_AND_WEDGE` (24),
`CLASS_MEASUREMENTS_THAT_MIRROR` (5) — generated by `finding_classes.py`, each inheriting the MAXIMUM
severity over its members so that consolidation cannot launder a blocker into a housekeeping note.

`render_class_document` derives that maximum correctly. **So the printed header is right the moment it
is written, and never again.** A consolidated member lives in `docs/staging/done/`; discharge it and its
own severity drops to `RECORDED`, the class's derived severity drops with it — and the class document on
disk goes on printing `BLOCKING`. `scan_staging_root` reads that stale header, `blocking_by_lane` hands
it to `supervisor._blocking_lane_draw`, and the lane stays frozen off a claim no control still stands
behind.

`check()` did not catch it. Its five rules — one class per finding, no unconsolidated sixteenth
instance, no resurrection, printed count equals list length, no document in two rooms — can each only
ever **ADD** an obligation. None of them could lower a severity. That is the same shape as the defect
the discharge header was built to fix, one layer up: **a new layer above a control inherited the
control's subject and not its release.**

## Observed, not inferred

Against the module at HEAD, in a fixture: consolidate one BLOCKING and one LATENT wedge finding, archive
both, then write a *valid* discharge onto the archived blocker.

```
archived member severity now = RECORDED
DERIVED class severity now   = LATENT
PRINTED class severity still = BLOCKING
HEAD (shipped) check ok?     = True   failures: []
```

Zero failures, on a document whose header was by then unbacked. The same fixture against the repaired
module reports `STALE SEVERITY … prints BLOCKING, instances derive LATENT`.

**The live tree was NOT in this state.** All five class documents' printed severities currently equal
their derived ones, and `--check` passed before this change and passes after it (56 instances across
five classes, 0 failures). This was a latent hole in the release path, not an active misreport — and
it would have opened the first time anyone discharged a consolidated member, which is precisely the
work rung 1c is asking for.

## The repair

Rule 6 in `check()`: the severity **printed** in each class document must still equal `class_severity`
over its instances. It is the only rule there that can lower a severity rather than raise one.

Two things it deliberately does not do:

- It does not treat an empty class as unbacked. `_write_class_documents` renders a document for every
  declared class, so four of the five live documents would fail on a stub. An empty class has no
  severity to derive; it is skipped. (My first cut got this wrong and the live tree said so.)
- It does not silently agree with a vanished archive. `instance_paths` still yields the missing paths,
  which read as unreadable, which `class_severity` already ranks `BLOCKING`, and rule 3 names the files.

## R15 — three mutations, each killing a named test

| Mutation | Pattern | Killed |
|---|---|---|
| **F** — `if False:` in place of the comparison | silent removal; reproduces the shipped state exactly | `test_mutation_f_…` |
| **G** — fire only when derived **>** printed | **fail-open**, the subtle one: escalation still works so the rule looks alive, but a *release* is silently dropped — "the blocker set can only grow", again | `test_mutation_g_…` |
| **H** — read the printed severity from `class_severity(instances)` | **tautology**: both sides from one source, so the comparison can never fail | `test_mutation_h_…` |

Each mutant is asserted to report `check().ok` on the defect state — the rule is proved absent, not
merely different. Anchors are asserted unique by `_load_mutant`, so no mutation is a silent no-op.

**Not-always-red**, both ways: a completed consolidation passes rule 6, an empty stub passes it, and the
live tree passes it. A control that is red on everything is not a control.

**R11 — the release has a tested effect, not an orphan transition.**
`test_re_rendering_releases_the_class_document_and_the_lane` asserts the class document *starts* in
`blocking_by_lane(...)["H_harness"]`, and that after discharge + `--render` it prints `LATENT`, `check()`
is green, and it is **gone from that lane's blocking set**. The release is verified at the real consumer,
not only in the parser.

**Fixture honesty.** OPS9 checks discharge evidence against the repo filesystem, so a fixture cannot
invent a falsifier; these tests name a real test node and
`test_the_discharge_evidence_this_fixture_relies_on_actually_exists` asserts it is still defined. If it
ever stops existing the discharge is refused and these tests fail — they cannot pass for the wrong reason.

**Evidence:** `tests/background/test_finding_classes.py` 40 passed; with
`test_finding_severity.py` + `test_supervisor_blocker_precedence.py`, **83 passed**.
`python3 -m background.finding_classes --check` → `check: PASS (0 failures)`.

## What this does NOT fix — filed, not silently carried

`background/finding_classes.py --check` **has no automated caller.** A repo-wide search finds no
scheduled job, no pre-commit gate, and no Python consumer outside its own tests; it runs when an agent
types it. This is true of all six rules, not just the new one, and it predates this change.

It is not a hole in the *release* — a discharge propagates through `--render`, and `--check` is the net
that catches a forgotten re-render. But an unrun net is thin, and this repo carries an entire
`CLASS_NO_CALLER_AND_NEVER_RUNS` class for exactly this shape.

Filed as a separate finding rather than fixed here, per SELF_INTERRUPT_DISCIPLINE (queue by default;
the supply of harness findings is infinite). Wiring `check()` into the supervisor draw or the
pre-commit gate changes what can freeze a lane and needs its own design and its own R15 proof — it is
not a line to append to this commit.

→ `WORKER_FINDING_THE_CLASS_CHECKER_HAS_NO_AUTOMATED_CALLER_2026-08-12.md`

## Why the eight are still eight

Rule 6 opens the release path for the three class documents; it does not walk through it. A class is
released by discharging its blocking members — 8 of 19 in `controls_that_cannot_fail`, and so on — each
with a named falsifier run green first. Not discharged here means not yet evidenced, never not blocking.
