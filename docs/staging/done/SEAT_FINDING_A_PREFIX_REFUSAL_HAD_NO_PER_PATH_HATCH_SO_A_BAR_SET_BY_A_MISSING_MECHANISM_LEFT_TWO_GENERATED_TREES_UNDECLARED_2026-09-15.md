# A prefix refusal had no per-path hatch, so a bar set by a MISSING MECHANISM — not by evidence — left two generated trees undeclared, and one of the two declines was refuted on its own instance

**Filed 2026-09-15, delivery seat.** Prereg:
`docs/staging/records/PREREG_WHETHER_A_PER_PATH_HATCH_ON_THE_PREFIX_REFUSAL_LETS_THE_TWO_DECLINED_TREES_BE_DECLARED_2026-09-15.md`,
written before any file under either candidate tree was opened.

The frame before this one declared `docs/status` and declined `site/state` and `docs/reports`,
stating the reason as structural:

> `WRITTEN_BUT_NOT_REPRODUCIBLE` is a per-path hatch and a PREFIX refusal has no equivalent. A tree
> holding one irreproducible record cannot be declared and then corrected, so the bar for a tree is
> *every* path under it, not most.

That is a bar set by a mechanism that does not exist yet. It is now built, and both trees are
declared on evidence.

---

## 1. The repair the drawn item asked for would have been a fail-open

The item said to give `offends()` an exception set **"the way the two oracles already have
`WRITTEN_BUT_NOT_REPRODUCIBLE`"**. Sharing that *set* is the defect, not the fix, and the two read
as interchangeable:

| | `WRITTEN_BUT_NOT_REPRODUCIBLE` | what `offends()` needs |
|---|---|---|
| question | does a REVERT lose content no run can recompute? | does a `file_scope` naming this STARVE its atom? |
| consumer | the reconciler's union | `gate_violations()`, the commit gate |
| a wrong member costs | a lane's real work is reverted | an atom starves invisibly — the G13 defect |

On the decisive case they are **opposite**. An accumulated ledger is irreproducible *because* every
run rewrites it — maximally dirty, therefore maximally starving.
`site/state/live_decisions_log.jsonl` would have been the shared set's first member under the newly
declared trees, and exempting it from `offends()` is the eight-day G13 starvation arriving through
the repair for a different defect.

So the new set is a different set with a narrow predicate: **a path under a declared generated tree
that no run writes at all** — an authored document inside a generator's tree. For that path and
only that path the prefix is wrong, the atom would not starve, and the refusal *"Scope the
GENERATOR, not the generated"* names a generator that does not exist.

`tests/tools/test_a_generated_tree_may_hold_an_authored_document.py::test_the_two_hatches_are_DISJOINT_and_must_stay_so`
is the control, and it is not ceremony: a path cannot be both *rewritten whole, irreproducibly* and
*written by no run at all*, so an overlap is one of the two entries being wrong about its subject.

## 2. The decline for `site/state` was wrong about its own instance, not only its bar

`live_decisions_log.jsonl` was named as the reason that tree could not be declared: an accumulated
ledger with "no hatch". **It needs none and can have none.** It reaches NEITHER oracle:

- `.jsonl` is not in `ARTEFACT_SUFFIXES` (`.json`, `.md`, `.sqlite`, `.csv`), so the tree-keyed door
  is shut however many trees are declared; and
- `tools/run_live_decisions.py` **appends** to it, and `"a"` is deliberately absent from
  `WRITING_MODE_CHARS`, so the write-keyed door is shut too.

No revert is ever offered on it, so there was nothing to hatch. Its **prefix refusal is correct and
is left standing**: an atom scoping a ledger every run appends to would starve, which is this
gate's entire subject. The decline rested on a harm that the module's two existing exclusions had
already prevented — and this was found by asking what the *consumer* reads, not by re-reading the
decline.

I also declined to add it to `WRITTEN_BUT_NOT_REPRODUCIBLE` defensively. That set's own staleness
control requires every member to be write-reached, so a defensive entry would read STALE and go
red. The existing control refused the reflex, which is what a good one does.

## 3. The evidence, file by file

**`site/state` — 50 tracked, all 50 a run's output. Declared with NO exception.**
8 write-reached; 40 `live_decisions_YYYYMMDD.json` snapshots under a **computed name**, which is
precisely why the scan resolves 8 and the density reads 0.160; `track_record_scorecard.json`
(`tools/generate_track_record_scorecard.py`); and the append ledger in §2.

**`docs/reports` — 33 tracked, 32 machine artefacts and ONE authored document.**
9 write-reached. `ANNUAL_REPORT.md` is rendered by `saas/reporting/annual_report.py`;
`SEGMENT_REPORT.md` has `DEFAULT_REPORT_PATH` in `saas/reporting/segment_report.py` and says
*"Generated by Phase 10a segment customer model"* in its own third line. The remaining JSON is
written under computed names (`path.with_name(path.stem + "_svt_segment_decisions.json")` in
`tools/measure_churn_heterogeneity.py:318`), and eight carry their own `how_to_regenerate`,
`producing_commit` or `generated_at` key.

`REPORTING_BACKLOG.md` is the exception, on **positive** evidence rather than the absence of a
generation stamp: no module in any scanned tree writes it. The one "producer" a name search returns
is `saas/reporting/annual_report.py`, which only ever **cites** it — including in a constant whose
text ends `(see REPORTING_BACKLOG.md)`. Naming is not the property; that asymmetry is the thing
`written_artefacts`'s docstring is at pains about, and it decides this case.

## 5. Q6 went the way I predicted, which fired my own stopping rule

**Q1 HELD** (`site/state` adds 0 live violations). **Q2 HELD** (`docs/reports`, 0).
**Q3 HELD** (union +13, predicted +1 to +15). **Q4 HELD** — `REPORTING_BACKLOG.md` was named in
advance as the authored document and is the only one. **Q5 HELD** — `site/state` needs no member of
the new set at all, so the mechanism is load-bearing for exactly one of the two trees.

**Q6**, the calibration: *does the new exception set change `violations()` on the live map today?*
I predicted **FALSE** and it is FALSE. The prereg's §3 stopping rule therefore fired, and it says
the exception ships **only if** it carries a control that can fail on tree state. So it does, and
that is the honest reason to believe it rather than the passing suite:

- `test_no_exempt_path_is_WRITE_REACHED_or_the_hatch_is_hiding_a_generator` — the fail-open
  direction. The moment any scanned module acquires a resolvable write site for an exempt path, the
  path IS generated and the exemption has become the invisible G13 defect. Red on tree state, every
  run.
- `test_every_exempt_path_is_UNDER_a_declared_prefix_or_it_is_dead_weight` — keyed to
  `GENERATED_TREES`, so retiring a tree reddens this instead of leaving a member quietly inert.
- The exempt branch is proven **reachable** on a synthetic map before it is proven correct, with the
  rendered sibling as the control — because no live `file_scope` takes it, and this project has
  three times shipped a guard that refused everything and passed every leg.

## 6. The mutations, and which leg caught each

Not "the suite is green" — three mutations were applied to the live module and the run restored it
byte-identical afterwards (`diff` clean, asserted in the script).

| mutation | caught by | |
|---|---|---|
| the hatch is emptied | `test_MUTATION_the_authored_document_is_exempt_and_everything_around_it_is_not` | 1 failed |
| the hatch is given a WRITE-REACHED member (`docs/reports/run_output_latest.json`) — a real generator it would hide | `test_no_exempt_path_is_WRITE_REACHED_or_the_hatch_is_hiding_a_generator` | 2 passed before it, so the file was reaching the tree |
| `("docs", "reports")` is dropped, leaving the hatch dead weight | the partition control again, on its `offends(GENERATED_NEIGHBOUR)` leg | 1 failed |

The third is worth stating precisely rather than flatteringly: the run used `-x`, so the partition
control fired first and I did not observe
`test_every_exempt_path_is_UNDER_a_declared_prefix_or_it_is_dead_weight` go red on that mutation.
It is reached by a different route — a member whose tree is retired while other trees stay declared
— which this mutation does not construct. The mutation is caught; the claim about *which* leg
catches it is narrower than it would be convenient to write.

The whole neighbouring suite is green: 91 passed across the gate's own R15 proof, the
unreproducible-record proof, the authored-tree-path proof and the reconciler's landing test.

## 7. The wart this exposes, counted rather than hidden

Declaring the two trees adds **4 union members that do not exist on disk**:
`site/state/sim_data.json`, `docs/reports/ledger_latest.json`,
`docs/reports/run_output_segments_latest.json`, and `docs/reports/run_output_*.json` — **a glob**,
from `tools/couple_value_based_pricing.py:499`.

This is the segment matcher's cross-product: it collects every string constant in ONE assignment
and pairs each artefact-suffixed one with the tree if both segments appear anywhere in that
expression. `tools/mirror_github_pages.py` lists `site/state/customer_sample.json` and
`site/data/sim_data.json` in one tuple, so `site/state/sim_data.json` is manufactured.

It is **pre-existing, not introduced**: 60 of the 246 union members before this change do not exist
on disk (most legitimately — runtime dotfiles that are gitignored). The rate does not move. It
degrades the safe way in every case, because a path that never appears in `git status` never
classifies anything. Recorded here so the next census does not rediscover it as news.
