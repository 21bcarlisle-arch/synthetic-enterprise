### The second generator, and its false citation

```python
def _mpan_check_digit(core8):
    """Published Elexon modulus-11 check-digit algorithm for the MPAN core ID."""
    weights = [3, 5, 7, 13, 17, 19, 23, 29]
    total = sum(int(d) * w for d, w in zip(core8, weights))
    return str((total % 11) % 10)
```

The published algorithm validates **the previous 12 digits of a 13-digit core** with **twelve**
weights `3,5,7,13,17,19,23,29,31,37,41,43`, sum mod 11 mod 10. This applies **eight** weights to an
**eight**-digit unique reference and emits an **11**-digit core. Its `top_line` is likewise 7 digits
(PC 2 + MTC **2** + LLFC 3) where the published structure is 8 — the MTC is a three-digit code.

This is the more dangerous of the two generators precisely because it is the better one: it selects a
DNO from a real ID range, builds a top line, and computes a genuine modulus-11 digit. An auditor
reading it finds a named source and a plausible implementation, and has to re-derive the algorithm
from the specification to discover it is wrong in three independent ways. **inferred:** the 8-weight
form is a real variant seen in the wild for the 8-digit unique reference alone; the defect is not
inventing a formula but applying it to the wrong span and then citing the other one.

**Source note (honest limit):** the primary Elexon knowledge-base pages returned 403 and 404 under a
browser user-agent this pass, so the 12-weight/13-digit reading rests on a **secondary** source
(Wikipedia, *Meter Point Administration Number*, fetched 2026-08-19, HTTP 200, four independent code
listings). **The finding does not depend on resolving that**: under either reading the
`company/crm` mint carries no check digit at all, the two published identifiers still contradict each
other, and the docstring still cites a span it does not use. Resolving the primary source is a step in
the repair, not a precondition for the finding.

### The validator is inverted, and cannot fail

Over all 20 live accounts:

```
company/crm mint: validate_mpan accepts 20/20;  published algorithm accepts  0/20
tools/      mint: validate_mpan accepts  0/20;  published algorithm accepts  0/20
validator's own test fixture 1012345678901 -> invalid (expects check digit 3, carries 1)
```

`validate_mpan` accepts every structurally empty identifier and rejects every one from the generator
that attempts a check digit, because `^\d{13}$` demands 13 and the more-nearly-correct output is 11.
Wired up as-is it would reject the better identifier and pass the worse one. Its certifying fixture is
itself invalid, so "valid" is defined by the same regex that checks it — an **R15 tautology**,
fail-open across the whole class. **Any repair must make the control fail on a named defect** (R15):
the mutation is a valid MPAN with its last digit incremented, which must be rejected.

## Why nothing fired

An AST census of every non-test `.py` gives **zero production importers** for
`company/billing/meter_points.py`, `company/crm/customer_registry.py` and
`company/market/dcc_meter_registration.py`. The generator, the validator and the DCC registration
model have never met at runtime. The identifiers reach the published site by a different path
(`process_run_complete` → `generate_customer_data`) that consults no validator at all.

**A census trap worth carrying (R10 relevance):** a substring search for `mpan` over this repo's
artefacts is contaminated by the word "company" — 440 hits in the published run output, **all 440**
inside `co-mpan-y`, against a word-boundary count of **zero**. Any control keyed on that substring
reports the identifier as abundantly present when it is entirely absent, and would pass while
measuring nothing.

## What the repair has to cover (R10 — not closeable as an instance fix)

1. **One generator, not two.** Two live minters for one identifier is the defect underneath the
   published contradiction; pick one, delete the other, and have the published surface read the same
   value the company believes.
2. **The referee is external.** The check digit must come from the published algorithm, with the
   primary source retrieved and cited, and the docstring must match the span it implements.
3. **A control that can fail** (R15), with the last-digit mutation above.
4. **The class, not the instance:** MPRN is minted by the same two modules and has, per the same
   page, no public checksum standard — so it may have **no referee at all**, which is a different
   and possibly unclosable leg. Name it rather than assume it is covered.
5. **Blast radius is unmeasured here.** 19 published customer files is what this pass counted; it did
   not count every consumer of either generator, and "count the consumers before replacing the one
   table" applies.
