# The committed feed states a supplier comparison that regenerating it withholds, and the page has been serving the stated one

**Class:** `figures_on_a_superseded_clock` (primary), `controls_that_cannot_fail` (secondary)
**Filed:** 2026-09-03, delivery seat, Lane 0, claim
`verdict-carries-the-redraw-range-not-a-bare-true`
**Subject:** `site/data/value_arms.json` → `realised.is_the_published_supplier`,
produced by `tools/generate_value_arms_data.py`.

**Found incidentally and not looked for.** I regenerated the feed to publish the re-draw mean and
diffed the result against the committed one. Two blocks moved. One was mine. This is the other,
and it is reported separately rather than folded into that commit's message, because a movement
nobody predicted riding inside a commit that predicted a different movement is how an unattributed
figure gets published here.

## What

At `a59a46bc7` (= `origin/main`), the **committed** `site/data/value_arms.json` carries:

```
realised.is_the_published_supplier.checked                = true
realised.is_the_published_supplier.same_supplier          = false
realised.is_the_published_supplier.published_run_net_gbp  = 138152.772886
realised.is_the_published_supplier.gap_gbp                = -7728.653570997762
statement: "The published run's net margin (£138,152.77) is NOT the baseline arm's
            (£145,881.43) -- they differ by £7,728.65. ..."
```

Regenerating that file **from HEAD's own generator, with no code change of mine**, gives:

```
realised.is_the_published_supplier.checked                = false
realised.is_the_published_supplier.same_supplier          = null
realised.is_the_published_supplier.published_run_net_gbp  = 131289.339938
realised.is_the_published_supplier.dashboard_net_gbp      = 138152.77
statement: "This feed cannot say whether the baseline arm is the supplier the site publishes.
            The run artefact it reads reports £131,289.34 and the figure the site actually
            publishes for the company reports £138,152.77 -- a gap of £6,863.43 -- so the two
            are not the same run and the claim is withheld ..."
```

## The attribution, run rather than argued

Three feeds compared key-by-key: the committed one, one generated by `git show HEAD:` 's copy of
the generator against today's artefacts, and one from my edited generator. The committed→HEAD diff
is exactly the six `is_the_published_supplier` keys above and nothing else. The HEAD→mine diff is
exactly `verdict_stability.redraw_mean_gbp`, `verdict_withheld_because` and `headline`. So the
supplier movement is **pre-existing at HEAD** and any regeneration surfaces it.

## Why it matters

The direction of the movement is the *good* one — a stated comparison becomes a withheld one with
a named reason and both numbers on the surface. That is fail-closed working correctly. The defect
is that **the committed artefact has been serving the stated version while the code that produces
it would refuse to state it**, and `£138,152.77` appears on the two sides of the two versions
meaning different things: it is the *run's* net in the committed file and the *dashboard's* net in
the regenerated one. A reader who diffed the page across the regeneration would see the same
£138,152.77 move from one role to the other with no note that it had.

Nothing controls the gap between "the feed on disk" and "the feed this code would produce". Every
control on this block asks whether the generator is honest; none asks whether the committed
artefact is what the generator currently says. That is the same shape as the drawn item that
produced this finding — a control on the numerator's provenance with nothing on the numerator.

## Not done in this bounded tick, and why

I did **not** re-key any control to close the staleness gap. The generated feed must ride in my
commit — it is produced wholesale and cannot be hand-carved without forging a generated artefact —
so this tick lands the regenerated block and names it. The control that would catch it (a check
that `site/data/value_arms.json` equals a fresh `generate()` at HEAD, or that the publish daemon's
regeneration is the only writer) is a separate subject with its own failure modes, and inventing
it at the end of a tick aimed at something else is how this repository grew 117 harness atoms.

**Owed next:** a control keyed to the property *"the committed feed is what this code produces"*,
and a decision on whether `is_the_published_supplier`'s two `£138,152.77`s should be distinguished
by name. Neither is costed here.
