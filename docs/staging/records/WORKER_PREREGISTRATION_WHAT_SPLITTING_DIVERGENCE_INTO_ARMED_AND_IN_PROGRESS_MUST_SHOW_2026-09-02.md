## The claim being tested

`background/tree_divergence.py` already measures divergence and already fired on the VAT hazard —
as **one of 272 files**, indistinguishable from 233 unattributed docs that are ordinary
work-in-progress. The alarm's own text ends "Report only — the publish gate's subject is HEAD, so
this blocks nothing."

**`divergence` is a concept that splits into two populations with opposite remedies, and we have
been publishing one count across both.** This is the CLAUDE.md shape — *before measuring a thing,
say what it is* — and the same failure as *average unit rate* and *bill shock*.

| population | tree content is… | remedy | today's signal |
|---|---|---|---|
| **IN PROGRESS** | novel, or newer than HEAD | *land it* | counted |
| **ARMED REVERT** | an **older committed version** of that path | *restore to HEAD* | counted identically |

An ARMED file is a loaded gun: the next *correct* pathspec commit that includes it silently reverts
whatever HEAD holds. That is how the canonical VAT repair came within one `git add` of being undone.

## Predictions — the MOVE, not an invariance

**P1 (the discriminator is sharp, not just another count).** Run on the real working tree, the armed
set will be **≤ 3 paths** and the divergence count will remain **> 200**, i.e. armed/total **< 5%**.
If the armed set is a large fraction of divergence, the split is not a discriminator and this
mechanism is not worth having — that refutes the whole item.

**P2 (it names the specific survivor).** The armed set on this tree will contain
**`site/data/weather.json`** and will **NOT** contain `company/billing/invoice.py` or
`tests/company/billing/test_invoice_characterization.py`, both of which I restored to HEAD earlier
this turn. This is the leg that would catch me having restored nothing.

**P3 (it can fail — mutation).** Two legs, and BOTH must be exercised or the control is a tautology
that returns every changed path:
- a file written back to an **ancestor** version → **fires**;
- a file with **novel** content (ordinary in-progress work) → **does NOT fire**.
The second leg is the load-bearing one. A "discriminator" that fires on both is just `git status`.

**P4 (fail-closed, per this module's own established discipline).** When git cannot answer, the
result is **`None` and a named reason**, never `[]`. `changed_paths` was repaired for exactly this
in `WORKER_FINDING_TREE_DIVERGENCE_FAILS_OPEN_TO_A_CLEAN_TREE`; a new field that fails open to
"nothing is armed" would reinstate that defect one field over.

**P5 (the bound is published, not silent).** History is searched to a bounded depth per path. A file
that hits the cap without a match is **not proven safe**, and the artefact must publish the depth so
the reader gets the bound the search earns. A silent cap reads as "we checked everything".

## What would make me abandon this

If P1 is refuted the split is noise and I should say so and delete the code rather than tune a
threshold until it looks useful. **Recorded before the run: I expect P1 to hold, and I am aware that
"my new mechanism is valuable" is the flattering answer and the one I should be hardest on.**
