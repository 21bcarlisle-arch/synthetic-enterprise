## CORRECTION, same turn, kept beside the claim it replaces

The paragraph above ended: *"for a regenerated document the sediment control's other remedy is the
right one: fewer channels that file, not a disposition route"*, and recommended running
`tools/staging_migrate_rooms.collapse_alarms()` as its own commit. **Both are wrong, and the
one-variable run refuted them in seconds.** `--dry-run` over the nine documents in the root emits
**nothing**: the collapse skips a group of one, and asking the grouping directly gives

      deadman_worktree_undeclared · delivery-lane-stranded · seat-claim
      seat-continuity · stretch-log · tree_divergence

One document per condition. `alarm_repetition`'s one-document-per-firing is **working**, and there
is nothing to fold.

**This also refutes the framing the drawn item handed me**, which named this family as its first
suspect on the reasoning that *"an alarm that re-files itself every cycle is a channel, not a
backlog"*. It does not re-file itself. Eight distinct conditions arose in the window and one was
dispositioned, so it IS a backlog — of nine live, separate machine complaints, several of them
about landing and worktree hygiene — and **neither of the sediment control's two remedies applies
to it.** Not "fewer channels": each document is one real condition and suppressing it loses the
condition. Not "a disposition route": there is no room for a live alarm, because it is work. The
remedy is doing the work each of the nine names.

I had predicted this family's net would be ≤ +2 for exactly the reason that turns out to be false,
so the pre-registration and the item's own suspicion were wrong in the same direction, from the
same unexamined assumption: that volume in a regenerated channel implies repetition.

## What is actually owed

Nine alarms, ranked below every human ask by design (`ORDER[KIND_ALARM] == 60`), which is correct
and is also why they accumulate: nothing above them ever empties. The honest exit test is **not**
"the root has fewer alarm documents" — that would be a count, and a count is what gets tidied. It
is *"every alarm in the root is a condition that is still true"*, which nothing currently asks:
`deadman_*` and `tree_divergence` in particular describe states that may well have cleared on their
own, and a self-clearing alarm that nobody re-asks is indistinguishable from a live one.

**Recommended, not asked:** give `alarm_repetition` a re-ask — a document whose condition no longer
holds archives itself with the evidence, and one whose condition still holds gains an instance line
rather than sitting unchanged. That is a producer-side change, it is the smallest mechanism that
can fail, and it is a separate turn's work. Not done here.
